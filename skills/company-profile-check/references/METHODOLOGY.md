# Profile Check Methodology

## Who reads a public profile

A buyer comparing vendors, a candidate before an interview, an investor before a call, a journalist on a deadline - and, more and more, the assistant each of them asks first. The assistant reads what is public, weighs it by who said it, and answers in one paragraph. An audit shows the company that paragraph and what it was built from.

## The unaided answer

An assistant with no tools answers from what it absorbed in training: old press, old versions of the company's own pages, other people's descriptions of it. That answer is what a buyer gets when they ask in passing, and it is usually older and vaguer than the record.

Capture it before reading anything, then compare:

| Unaided answer against the record | Usually means | For the user |
| --- | --- | --- |
| Agrees | The fact is old, stable and widely published | Nothing to do |
| States a different value | Often an older one that is still widely published. It is the assistant's memory, not a past value on record: do not present it as an old price or figure | Publish the current value where it will be read and repeated |
| States something the record does not hold | It came from a source LMTY has not read, or it is invented | Ask the user which. An invented fact is worth knowing about |
| Says nothing where the record has a fact | The fact is recent or sits on few pages | More places stating it, in plain text |
| Knows nothing of the company | Too new or too little written about it | The whole list under "Missing" matters more |

Limits to state in the output: this is one assistant and one model on one day; another would answer differently; and the same assistant with a search tool would answer from live pages instead. The skill does not ask other assistants.

## Five kinds of finding

| Kind | What it looks like | Whose call |
| --- | --- | --- |
| Missing | A section with nothing in it | The auditor finds it; the user says whether it matters |
| Stale | A fact whose last source is old | The auditor finds it; the user says whether it still holds |
| Contradictory | Two values for one fact | The auditor finds it; the user says which is right |
| Unverified | A statement resting on one outside voice | The auditor lists it; the user sorts it |
| Off-message | The summary an outsider reads does not match what the company says of itself | The auditor shows both; the user decides |

There is no sixth kind called "wrong". The auditor cannot see the truth, only the record.

## Why a section is empty

An empty or thin section has two possible reasons, and the record does not choose between them: LMTY has not read it, or the company's pages do not show it. An empty section says what LMTY holds, not what the site shows. Give both reasons, then offer a check the owner can answer.

| Empty or thin section | A reader would expect | The check to offer, as a question | Where the fix belongs once the owner answers |
| --- | --- | --- | --- |
| Founding, headquarters, headcount | The year, the place, a size | "Does your about page state these in text, not in an image?" | Yes: with LMTY. No: the about page |
| Leadership | Names and titles | "Does your site have a team page with names and titles in text, one that loads without scripts?" | Yes: with LMTY. No: a team page |
| Plans and prices | Plan names and listed prices | "Does your pricing page show prices, not a form or 'contact sales' only?" | Yes: with LMTY. No: the pricing page. If prices are private by choice, the gap is correct |
| Customers | Named customers | Read the product's profile first: customers are recorded there, so a company profile's count reads zero whatever its customers page shows. When the product holds none either: "Does your site have a customers page at a stable address, with names in text and not only logos?" | Yes: with LMTY. No: a customers page; case studies |
| Certifications | The certifications held | "Are they on a security or trust page, not only in a PDF or a sales deck?" | Yes: with LMTY. No: a security or trust page |
| Funding and investors | Rounds and backers | "Is the round announced on a page that is still up: yours, or an investor's portfolio page?" | Yes: with LMTY. No: a news or about page; the investors' own portfolio pages |
| Open roles | Current openings | "Does your careers page link the board the jobs are on?" | Yes: with LMTY. No: a careers page linking the board |
| What leaders have said | Public statements | "Have your leaders spoken in public, on a recording or in print?" | Yes: with LMTY. No: not a fix; a choice |
| Upcoming events | Announced dates | "Is anything announced publicly, with a date?" | Yes: with LMTY. No: not a fix; a choice |

The two columns of the name and channel check below hold here, and in the ranked fixes: missing from LMTY's record, and missing from the company's own site, with no row moved between them by inference. The record tells the two apart only where it marks an entry as removed or no longer listed on the company's pages. Only such an entry supports "your pages do not show it" on its own.

Never write that the site lacks a page. You have not seen the site, only what LMTY read of it.

Offer a check only for a section a reader would expect on a company's own pages and the record does not hold. None for something the record already holds from the company's page (a founding year read from the about page needs no check that the page states it), and none for history a page cannot show: past prices, retired plans, earlier wording.

## The name and channel check

A reader who meets the company under an old name, or on an account that is not the company's, reads about a different company. The check lays out what the record holds for the owner to confirm.

| Row | Read | It comes with |
| --- | --- | --- |
| Name | The name on the profile | Nothing more |
| Former names | The facts recorded as former names | Grade, last seen, source |
| Product names | The product profiles the company is tied to as the one offering them | The tie, as the record gives it |
| Aliases | Nothing: the record keeps no list of aliases or trading names | - |
| Website | The website on the profile, which can be empty | Nothing more |
| Accounts | The accounts listed on the company's profile and on its main product's: platform, handle, address, and whose the record says each is | No grade, no date, no source: write "not given" |
| Pages read | The pages of the company's site among the sources of the answers read, and the page titles on record | The date each was read |

Absence goes in one of two columns, and the two are never merged:

| Column | Means | What goes in it |
| --- | --- | --- |
| Missing from LMTY's record | The record does not hold it. It may exist | No alias list, always. No former name on record, no product profile tied to the company, no website on the profile, no accounts listed, no page of the company's site among the sources read |
| Missing from the company's own site | The record read the site and it is not there | Only an entry the record marks as no longer listed on the company's pages, or shows as removed from them, with the date |

- never move a row from the first column to the second by inference. An empty list says what LMTY holds, not what the site shows
- a name or account the record holds only from someone else's page is not "missing from the site". The source column already says whose page it came from
- when the record marks nothing as no longer listed or removed, the second column reads "nothing the record can place here", once
- the fixes differ. The first column: publish it where it can be read, or raise it with LMTY when it is already published. The second: restore it to the page, if it belongs there

Under its name, not the company, for the user to review:

- other profiles the search returned for the name, each with its type, name and website
- accounts listed that the record gives to someone other than the company or its product: a founder, a community

The record marks nothing as a namesake, a reseller or a fan account, so the check labels none. Each row is a question, "is this yours?", and the user's answer is the finding.

## Stale

A fact is worth a second look when its latest source is older than the thing it describes usually lasts:

| Fact | Second look after |
| --- | --- |
| Headcount, open roles | 3 months |
| Plans and prices | 3 months, or any pricing change the user mentions |
| Leadership roles | 6 months |
| Funding, valuation | The last round the user knows of |
| Description, category | Any launch, rebrand or pivot since it was written |

These are prompts for a question, not rules. Ask "still true?"; do not write "outdated".

## Ranking the fixes

Score nothing. Sort by two questions, in this order:

1. **How many readers does it reach?** The summary and the headline facts reach everyone. A detail in a deep section reaches few.
2. **How wrong does it leave them?** A wrong price or a departed chief executive misleads a decision. A missing founding year does not.

Then note the effort, so the user can pick the cheap high-reach ones first: a text change on a page they control is minutes; a third party's page is a request; a rumor is a counter-statement, and time.

## Where a fix happens

| The problem is on | The fix |
| --- | --- |
| The company's own page | Change the page. The record follows when the page is next read |
| The company's own profile on a third-party site | Update that listing |
| A press article | Ask for a correction if it is an error of fact; otherwise publish the current figure yourself |
| A single post | Cannot be removed. Publish the true statement where it will be read and cited |
| The profile itself, with the source correct | Raise it with LMTY |
| An empty section, when the company's page already shows it | Raise it with LMTY |

Write the fix as an instruction someone could carry out: which page, which line, what it should say - leaving the true value for the user to supply. The ranked list holds only fixes for what the record got wrong or what the user confirmed. An unanswered check is not a fix: it stays under "Missing" and takes none of the ten places.

## What others say

List, do not rule. For each outside statement give who, where, when and the exact words.

Offer the user three bins and let them sort:

- **untrue, worth answering:** a counter-statement on a page the company controls
- **true, uncomfortable:** nothing to correct; possibly something to address
- **harmless:** leave it

Never advise trying to have criticism taken down.

## People

The same boundary as everywhere in this pack: roles, employers, dates and public statements. When the subject is the user themselves, it still holds. Nothing private is sought, and nothing private that turns up is repeated.

## Length

The findings table is the audit. Keep the prose around it to a paragraph per section, and cap the ranked list at ten. An audit with forty findings gets none of them fixed.
