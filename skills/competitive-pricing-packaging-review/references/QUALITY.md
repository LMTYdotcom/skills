# Output Quality Standard

Every LMTY-authored PMM skill should produce work that a strong PMM could use immediately.

## Standard qualities

### Decision useful

The output should help someone make, prepare for, communicate, or execute a decision.

Do not stop at a research dump when the skill's job is downstream of research.

### Compressed

Prioritize what matters. The existence of more source material is not a reason to include it.

### Specific

Prefer exact competitor, plan, feature, segment, claim, date, evidence, and implication over generic language.

### Honest

Expose uncertainty and missing context. Do not make the output weaker by pretending to know more.

### Audience aware

A board brief, sales battlecard, and launch readiness review should not read like the same artifact with different headings.

### Reusable

Default outputs should be easy to paste into docs, Slack, decks, launch plans, or other work products.

## Recommended output anatomy

Most outputs should contain some subset of:
- executive answer or TLDR
- what changed or what is true now
- why it matters for the stated job
- evidence and freshness
- gaps, risks, or unresolved questions
- action options or next steps
- appendix or source table when necessary

## Artifact discipline

When the user asks for a finished reusable artifact, produce the artifact, not a lecture about how to make one.

## Delivery

Return the artifact in the reply, in full. Then offer to save it.

Do not write a file unless the user asked for one. A skill that silently writes `battlecard-vs-competitor.md` and replies with a summary has taken a decision that was not its to take: the user cannot see what they are about to circulate, and the file lands wherever the agent happened to be.

- default: the whole artifact inline, followed by one line offering to save it
- asked for a file: write it, then say the path and what is in it
- artifact too long to be readable inline: still lead with the artifact, and put the deep evidence in an appendix section rather than moving the whole thing to disk

Never reply with only highlights of an artifact the user cannot see.

## Comparison discipline

Avoid feature-table theater.

A comparison should emphasize:
- dimensions customers actually evaluate
- meaningful parity and difference
- who cares about each difference
- evidence
- where the home product is weaker

## Recommendation discipline

A useful PMM recommendation connects:

**market evidence + customer/deal evidence + company strategy + timing**

If one or more inputs are unavailable, reduce the strength of the recommendation rather than hiding the gap.
